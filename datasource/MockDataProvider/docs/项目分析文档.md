# MockDataProvider 精简说明（<200行）

目标：模拟以太坊节点的最小可用数据源，用于联调与故障注入验证。文档仅刻画当前机制与可落地的优化点，避免过度设计。

——

一、模块概览

- 技术栈：Go 1.20，Gin（HTTP），Gorilla WebSocket，Viper（配置），JSON-RPC 2.0。
- 提供能力：
  - HTTP JSON-RPC：查询区块（按号）、当前高度、健康检查。
  - WebSocket：按间隔推送新区块头（可订阅/退订）。
  - 故障注入：限流/超时/断连/随机错误/数据丢失（按概率）。
- 主要用途：在真实链路复杂或不稳定时，为接入层、聚合器、前端联调提供可控的数据流与异常场景。

——

二、当前机制（最小实现）

1) HTTP 控制器（internal/controller/http.go）
- 路由：`/rpc`（JSON-RPC 2.0），`/healthz`（存活探测）。
- 方法：
  - `eth_blockNumber`：返回当前高度（十六进制）。
  - `eth_getBlockByNumber`：按块号返回确定性区块头（含 parentHash、hash、number、timestamp）。
- 故障注入：
  - 按配置概率返回 5xx、延迟、限流（429）或空响应（模拟超时）。

2) WebSocket 控制器（internal/controller/websocket.go）
- 协议：Gorilla WebSocket，简单订阅模型（单主题：newHeads）。
- 推送：定时器按 `blockInterval` 生成并广播新区块头；支持连接级断连注入。
- 故障注入：
  - 概率性断连；概率性跳块（数据丢失）；概率性心跳异常（不发 ping/pong）。

3) 数据生成器（internal/generator/data_generator.go）
- 状态：`currentBlockNumber`、`lastBlockHash`。
- 生成：
  - `GenerateNextBlock()`：高度 +1，hash 由上一块与高度派生（可重复构建）。
  - `GetBlockByNumber(n)`：使用确定性函数重建目标块，保证 HTTP/WebSocket 一致性。
- 时间：`timestamp = start + (height * interval)`，易于定位回放源。

4) 配置（internal/config/config.go + configs/config.yaml）
- server：host/port。
- data：`startBlockNumber`、`blockInterval`（ms）。
- fault：HTTP/websocket 级别的多种概率项（0.0~1.0）。
- 特点：集中管理、默认值兜底、环境变量覆盖。

——

三、接口约束与示例

1) HTTP JSON-RPC（POST `/rpc`）
- `eth_blockNumber`
  - 请求：`{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}`
  - 响应：`{"jsonrpc":"2.0","id":1,"result":"0x2a"}`
- `eth_getBlockByNumber`
  - 请求：`{"method":"eth_getBlockByNumber","params":["0x2a", false]}`
  - 响应：`{"result": {"number":"0x2a","hash":"0x...","parentHash":"0x...","timestamp":"0x..."}}`

2) WebSocket（`/ws`）
- 订阅：`{"jsonrpc":"2.0","id":1,"method":"eth_subscribe","params":["newHeads"]}`
- 推送：`{"jsonrpc":"2.0","method":"eth_subscription","params":{"subscription":"...","result":{blockHeader}}}`
- 退订：`{"method":"eth_unsubscribe","params":["<id>"]}`

——

四、运行与集成边界

- 运行方式：`main.go` 启动 HTTP/WS；无需外部依赖。
- 可观测性：基础日志（启动、订阅、错误）、最小健康检查。
- 一致性：
  - HTTP 历史查询与 WS 推送共享确定性生成规则，避免“查到与收到”不一致。
- 性能与限流：
  - 以“稳定推送流 + 轻量查询”为目标，无需追求高吞吐。

——

五、已知限制（当前版本）

- 只覆盖区块头，不含交易/日志。
- WebSocket 仅支持单主题（newHeads）。
- 故障注入为静态概率模型，不支持时间窗/节流模式。
- 不提供持久化与回放，仅靠确定性函数重建历史。
- 没有分片或多实例协调能力。

——

六、潜在优化点（按收益/工作量排序）

1) 故障注入增强（高收益/低成本）
- 增加“阶段型”注入：按时间窗或触发条件调整概率（如前5分钟正常，后5分钟频繁超时）。
- 支持“黑名单/白名单”维度：按请求方法、连接ID、IP 注入不同故障。
- 提供“场景预设”：延迟抖动、间歇性 5xx、背压丢包等一键切换。

2) 数据面扩展（中收益/中成本）
- 可选输出交易数量（随机或固定），用于压测下游解析分支。
- 增加 `eth_getBlockByHash` 与 `eth_subscribe` 的 logs 主题（简单 mock）。

3) 推送控制（中收益/低成本）
- 动态调节 `blockInterval`（运行时变更），便于模拟快/慢链情形。
- “跳块策略”可配置：按固定周期跳过一块/一段，提高可重现性。

4) 可观测性（中收益/低成本）
- 简单指标：当前连接数、推送速率、丢包/断连计数、各类故障命中数。
- 增加 `/metrics`（Prometheus 友好），便于联调压测。

5) 配置与控制台（中收益/中成本）
- 热更新配置（文件/HTTP 控制面）；最常用项（概率、间隔）在线调整。
- 提供简易 Web 控制台页面（可选），查看状态与切换场景预设。

6) 回放/基线（低收益/中成本）
- 支持“固定随机种子”，跨实例生成完全一致的数据流，便于 A/B 对比。
- 录制/回放少量样本（仅头部），复现实验结果。

7) 稳定性（低收益/低成本）
- 限速与背压：当订阅过多或消费端卡顿时，降速而非堆积。
- WS 心跳治理：统一 ping/pong 周期，异常主动断开，避免僵尸连接。

——

七、裁剪原则（保持“够用即可”）

- 只保留：区块头、newHeads、基础 JSON-RPC、概率型故障。
- 不引入：复杂多链、多主题丰富语义、完整交易/日志模拟、持久化存储。
- 优先实现：易控制、可观测、易复现实验的功能。

——

八、结论

当前 MockDataProvider 已满足联调与故障注入的基本需求。后续若需要更贴近生产，只需在故障注入的可编排性、推送节奏控制、可观测与少量数据面扩展上做增量增强，保持整体简单可控，不将其演化为“另一个真实链节点”。
