## 3. 问题明细（背景、影响、建议）

### NF-01 队列模式“成功”上报过早，失败可静默丢失
- 核实证据：`internal/role/role.go:545`、`internal/role/role.go:558`、`internal/role/role.go:1103`、`internal/role/role.go:1133`
- 背景：队列模式下，消息仅入队成功就调用 `reportSuccess`；消费侧 handler/sink 错误仅日志后 `continue`。
- 影响：控制面看到“成功”，但数据可能未落地；SLA、补偿、计费统计会失真。
- 建议：
1. 状态拆分为 `caller_success`、`pipeline_success`、`sink_success`。
2. 消费失败引入重试队列与 DLQ，失败计数打点并告警。
3. 状态上报带 `stage` 与 `error_class` 字段，支持回放定位。
- 验收标准：同一 task_id 出现 sink 失败时，不允许上报最终 success。

### NF-02 WebSocket 链路仍存在无界缓冲风险（并发子问题已部分修复）
- 核实证据：`internal/caller/native_call_websocket.go:313`、`internal/caller/native_call_websocket.go:779`、`internal/protocol/websocket.go:349`、`internal/protocol/websocket.go:141`
- 背景：`msgBuffer` 持续 append，仅在 `CallOnce` 时整批清空；底层 `msgChan` 满时会丢包。`Connect` 已用 `loopsStarted` 避免重复起读/心跳循环。
- 影响：慢消费时内存增长不可控；丢包后上游与下游序列偏离，触发更多 backfill。
- 建议：
1. `msgBuffer` 改为有界环形缓冲（按条数和字节双阈值）。
2. 明确丢弃策略（丢新/丢旧/按 stream 丢弃）并暴露指标。
3. 在 backpressure 状态下主动降频订阅或触发快照修复。
- 验收标准：压测下内存曲线可封顶，且丢包率与 backpressure 指标可观测。

### NF-03 Backfill 指令通道可能静默丢弃
- 核实证据：`internal/role/role.go:156`、`internal/handler/integrity/scheduler.go:103`
- 背景：backfill channel 固定容量 256；调度侧非阻塞发送，满了直接 `false`。
- 影响：高峰期 backfill 请求丢失，数据缺口长期存在，且无强反馈。
- 建议：
1. 改为“阻塞写 + 超时 + 指标”，超时后进入持久化补偿队列。
2. 为不同 backfill 类型设独立队列与限额，避免相互挤压。
- 验收标准：队列满时必须出现可检索告警事件，且补偿可重放。

### NF-05 kafka_command 提交时机早于业务完成
- 核实证据：`internal/emitter/kafka_command.go:135`、`internal/emitter/kafka_command.go:139`
- 背景：`fire(payload)` 后立即 `CommitMessages`，未与“处理成功”绑定。
- 影响：消费者重启或下游失败时无法重放，形成隐性数据丢失。
- 建议：
1. 引入 `fire` 执行结果回传，按结果提交 offset。
2. 或采用幂等命令模型，允许 at-least-once 重放。
- 验收标准：故障注入下，未完成任务不会提交 offset。

### NF-06 控制面 API 默认鉴权弱，且缺少服务端超时
- 核实证据：`configs/base.yaml:13`、`internal/api/server.go:72`、`internal/api/server.go:48`
- 背景：token 为空时直接放行；`http.Server` 未设置 Read/Write/Idle 超时。
- 影响：内网横向访问、慢请求占满连接、误操作停启 role。
- 建议：
1. 生产环境强制非空 token（启动前校验）。
2. 设置 `ReadHeaderTimeout/ReadTimeout/WriteTimeout/IdleTimeout`。
3. 加限流与审计日志（含调用人、来源 IP、变更摘要）。
- 验收标准：空 token 配置在生产模式启动失败；慢请求不再长期占用连接。

### NF-07 datasource 自动注入鉴权头未展开环境变量
- 核实证据：`internal/config/config.go:655`、`internal/config/config.go:661`、`internal/caller/native_call_http.go:316`
- 背景：注入头值形如 `${ENV}`，HTTP caller 发送前不做 `os.ExpandEnv`。
- 影响：请求携带字面量占位符，导致鉴权失败且定位困难。
- 建议：
1. 在配置加载阶段统一展开变量。
2. 缺失变量时 fail-fast，并输出明确变量名。
3. 对敏感头值增加脱敏日志。
- 验收标准：启动时缺失密钥立即报错，运行时不出现 `${...}` 头值。

### NF-08 可观测性定义较多但主链路未接线，HTTP 状态码标签存在 bug
- 核实证据：`cmd/worker/main.go:74`、`internal/observability/metrics/metrics.go:432`
- 背景：当前仅看到 `SetBuildInfo` 被调用；核心 `Record*` 系列未接入主流程。且 `statusCode` 被转成 rune 字符。
- 影响：无法按 role/caller/sink 定位性能与错误；HTTP 指标标签污染。
- 建议：
1. 在 caller/queue/handler/sink/backfill 关键路径接入指标。
2. 修复标签为 `strconv.Itoa(statusCode)`。
3. 增加最小 SLO 看板（吞吐、错误率、延迟、积压）。
- 验收标准：压测与故障场景下可通过指标定位瓶颈与失败阶段。

### NF-09 FileSink 关闭阶段依赖外部 Python 脚本
- 核实证据：`internal/sink/file.go:442`、`internal/sink/file.go:445`
- 背景：关闭时执行相对路径脚本 `automation/ops/sqlite/query.py ingest`。
- 影响：部署目录变化、Python 运行时缺失、退出阶段阻塞都会影响稳定性。
- 建议：
1. 元数据写入改为进程内实现（Go SQLite 客户端）。
2. 若短期保留脚本，改为异步任务并设置硬超时与重试。
- 验收标准：无 Python 环境时主进程仍可有序退出且不丢关键结果。

### F-01 finality gate 存在自锁路径
- 核实证据：`internal/handler/integrity/gate.go:101`、`internal/handler/integrity/gate.go:113`、`internal/handler/integrity/sequence_engine.go:479`
- 背景：`ShouldPass` 依赖 `confirmedSeq`，但 `confirmedSeq` 在 `OnDelivered` 后推进；首次事件无法通过导致无法触发推进。
- 影响：diff 消息长期堆积、延迟持续增长、频繁触发补数。
- 建议：
1. 将 finality 推进改为“接收即入窗口”，不依赖已投递事件。
2. 引入状态机测试覆盖首包、乱序、快照切换。
- 验收标准：在无快照场景下，finality=N 仍能稳定前进并持续下发。

### F-02 datasource 配置 schema 与样例不一致
- 核实证据：`internal/config/config.go:91`、`configs/base.yaml:28`、`internal/config/config.go:612`
- 背景：`DataSourceConfig` 无 `base_url/rate_limit` 字段；配置样例大量使用。注入逻辑只认 `rate_limit_profile`。
- 影响：配置“看起来正确”但运行不生效，造成隐性配置债务。
- 建议：
1. 统一 schema：要么支持 `base_url/rate_limit`，要么删除样例中的旧字段。
2. 启动时对未知字段告警或报错。
- 验收标准：示例配置可被完全解释，关键字段无静默忽略。

### F-03 kafka_command 校验与运行行为冲突
- 核实证据：`internal/config/config.go:503`、`internal/emitter/kafka_command.go:39`
- 背景：校验要求 `emitter_config.brokers`，但运行时支持从环境变量读取 brokers。
- 影响：合法配置被 validate 拒绝，阻碍 CI/CD 与动态下发。
- 建议：
1. 校验规则与运行时保持一致：`brokers || env` 任一满足即可。
2. 返回统一错误文案，明确可用环境变量名。
- 验收标准：仅配置 topic + 环境变量 brokers 时通过 validate 且可启动。

### F-04 `roles_localfile.yaml` 与当前 RoleConfig 不兼容
- 核实证据：`configs/roles_localfile.yaml:48`、`internal/config/config.go:17`
- 背景：旧文件使用 `data_form/url_config/sink_config`，当前模型使用 `emitter/caller/handlers/sink`。
- 影响：通过 `--roles` 加载时高概率校验失败，示例误导新接入方。
- 建议：
1. 提供迁移脚本（old schema -> new schema）。
2. 文档标注旧文件“仅历史参考，不可直接运行”。
- 验收标准：示例 roles 文件可直接通过 `ValidateRoles`。

### F-05 订单簿状态按 symbol 全局共享
- 核实证据：`internal/resource/orderbook/store.go:7`、`internal/resource/orderbook/store.go:17`
- 背景：全局 map key 仅 symbol，未隔离 role/exchange。
- 影响：多 role 同 symbol 时状态串扰，导致订单簿错误。
- 建议：
1. key 扩展为 `exchange|symbol|role_id`。
2. 增加隔离性测试（同 symbol 多 role 并行）。
- 验收标准：并行 role 不互相影响，回归测试稳定通过。

### F-06 batch_file caller 绕过 pipeline 语义
- 核实证据：`internal/caller/batch_file_caller.go:237`、`internal/caller/batch_file_caller.go:250`
- 背景：caller 内直接落盘并生成 manifest，返回空消息。
- 影响：handler/sink 治理能力失效（统一重试、审计、指标不可复用）。
- 建议：
1. 让 caller 仅产出消息；落盘与元数据归 sink 处理。
2. 过渡期可增加“兼容模式”，逐步切换。
- 验收标准：batch_file 链路可复用统一 handler/sink 观测与失败处理。

### F-07 `sink_topic` 配置易误配
- 核实证据：`internal/handler/hyperliquid_handlers.go:268`、`internal/sink/kafka.go:347`
- 背景：handler 写 `metadata["sink_topic"]`，但 Kafka sink 仅在配置了 `topic_field` 后才读取该字段。
- 影响：配置了输出 topic 却未生效，消息落入默认 topic。
- 建议：
1. 对 `sink_topic` 设默认映射（未配置 `topic_field` 时自动尝试）。
2. 启动期做配置一致性校验并给出提示。
- 验收标准：未配 `topic_field` 但消息含 `sink_topic` 时有明确行为与日志。

### A-01 handler 通过 metadata 传递指针对象，耦合强
- 核实证据：`internal/handler/parser/binance_parser.go:82`、`internal/handler/orderbook_handlers.go:162`
- 背景：上游 handler 把结构体指针塞进 metadata，下游按具体类型断言。
- 影响：强依赖执行顺序与进程内语义，不利于插件化和跨进程扩展。
- 建议：
1. 用 typed envelope（稳定 schema）替代裸指针传递。
2. handler 之间只通过可序列化数据交互。
- 验收标准：任一 handler 可独立替换，且不依赖上游具体 Go 类型。

### A-02 Domain 仅在配置层存在，运行态不可治理
- 核实证据：`internal/config/config.go:16`、`internal/role/role.go:26`
- 背景：`RoleConfig.Domain` 有定义，但 `Role` 运行结构不承载。
- 影响：无法按 domain 进行路由、限流、灰度与可观测聚合。
- 建议：
1. 在运行态保存 domain，并贯穿日志/指标/控制面。
2. 支持 `apply/stop` 按 domain 操作。
- 验收标准：可按 domain 查询与治理 role 生命周期。

### A-04 Caller 职责边界不统一
- 核实证据：`internal/caller/batch_file_caller.go:250`
- 背景：部分 caller 仅拉取，部分 caller 同时承担落盘与编目。
- 影响：抽象层次混乱，故障治理和测试策略难统一。
- 建议：
1. 定义 caller 契约：仅负责“取数并产出 message”。
2. 把副作用统一下沉到 sink。
- 验收标准：caller 包不再直接操作最终存储介质。

### A-05 缺少配置版本化与迁移机制
- 核实证据：`internal/config/config.go:166`、`configs/roles_localfile.yaml:44`
- 背景：`LoadRoles` 不含 schema version，旧新格式并存且缺少迁移层。
- 影响：配置演进成本高，跨团队协作易踩坑。
- 建议：
1. 引入 `apiVersion/schemaVersion`。
2. 提供版本迁移器与兼容窗口策略。
- 验收标准：旧版本配置可被显式迁移并输出变更报告。

## 4. 过时项修正说明

### NF-04 Sink 写入缺乏超时控制（已缓解）
- 核实证据：`internal/sink/kafka.go:127`、`internal/sink/kafka.go:194`
- 结论：当前已有 `write_timeout_ms` 与默认 5s 超时控制，原描述不再准确。
- 后续建议：保留该条作为“配置校验项”而非“缺陷项”，关注超时值是否与业务 SLA 对齐。

### NF-10 测试覆盖为 0（不成立）
- 核实证据：`internal/api/server_test.go`、`internal/protocol/websocket_test.go`、`internal/role/manager_test.go` 等
- 结论：已有测试文件，不是 0。
- 修正文案建议：改为“核心主链路端到端回归不足，需补齐 queue/sink/finality 集成测试”。

### A-03 控制面 Apply 是 replace-all（不成立，需重述）
- 核实证据：`internal/role/manager.go:223`、`internal/role/manager.go:288`
- 结论：现实现为增量计划（add/update/remove/unchanged），不是简单全量替换。
- 仍存缺口：缺少声明式 reconcile 的状态收敛、分批灰度、回滚策略编排。
